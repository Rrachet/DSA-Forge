# The 100-Problem Interview Track

A curated interview-preparation track designed around **patterns**, not random problem volume.

The goal is to make each problem answer four questions:

1. What pattern is this testing?
2. What is the simplest correct approach?
3. What invariant makes the optimal approach work?
4. What are the time and space trade-offs?

## Progress

**100 problems · 10 patterns · 3 difficulty bands**

- 🟢 Foundation: 1–30
- 🟡 Interview: 31–75
- 🔴 Advanced: 76–100

## Rules

- Solve without looking at the solution first.
- Write complexity before coding.
- Add at least one edge case.
- Prefer reusable patterns over memorised tricks.
- After solving, explain the solution aloud as if in an interview.

## Recommended progression

Do not chase completion speed. The target is **pattern recognition + clean implementation + explanation**.

After every 10 problems, revisit the pattern notes in `docs/patterns.md` and write down which signals told you to choose that technique.
